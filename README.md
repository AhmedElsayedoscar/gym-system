# سيستم إدارة الجيم

إدارة الأعضاء والاشتراكات وتسجيل الحضور بالـ QR. واجهة عربية بالكامل (RTL).

السيستم مكتوب **بدون أي مكتبات خارجية**: السيرفر والـ QR وقاعدة البيانات كلها مدمجة في Node.js نفسه، فمفيش `npm install` ومفيش حاجة تتكسر بعد التحديثات.

## التشغيل

المطلوب: **Node.js 22.13 أو أحدث** فقط.

```bash
ADMIN_PASSWORD="كلمة-سر-المدير" STAFF_PASSWORD="كلمة-سر-الاستقبال" GYM_NAME="اسم الجيم" npm start
```

بعدها افتح `http://localhost:3000`.

> لو ما حددتش كلمات المرور هتشتغل بـ `admin123` و `staff123` ومعاها تحذير في الشاشة. **غيّرهم قبل التسليم للعميل.**

### متغيرات الإعداد (كلها اختيارية)

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `ADMIN_PASSWORD` | `admin123` | كلمة سر المدير (كل الصلاحيات) |
| `STAFF_PASSWORD` | `staff123` | كلمة سر الاستقبال |
| `GYM_NAME` | `الجيم` | الاسم اللي بيظهر في الشاشة والكارت |
| `PORT` | `3000` | رقم المنفذ |
| `DATA_DIR` | `./data` | مكان قاعدة البيانات |
| `TZ_NAME` | `Africa/Cairo` | المنطقة الزمنية لحساب "النهارده" |

البيانات كلها في ملف واحد: `data/gym.db`. **النسخ الاحتياطي = نسخ المجلد `data`** (يفضل يوميًا).

## الصلاحيات

- **الاستقبال (staff):** إضافة أعضاء، تجديد الاشتراكات، تعديل البيانات، شاشة المسح، عرض الحضور.
- **المدير (admin):** كل ما سبق + إدارة الباقات، حذف الأعضاء، إلغاء اشتراك مسجل بالغلط.

## طريقة الاستخدام

1. **الباقات:** فيه 4 باقات افتراضية (شهري / 3 شهور / 6 شهور / سنوي) **بأسعار أمثلة**. عدّلها من صفحة "الباقات".
2. **عضو جديد:** من صفحة الأعضاء، ممكن تسجل الاشتراك مع العضو في نفس الخطوة. السيستم بيولّد له كود عشوائي (`GYM-XXXXXXXX`) وQR.
3. **كارت العضو:** من صفحة العضو اضغط "طباعة الكارت" (مقاس كارت ائتمان 86×54 مم).
4. **الحضور:** افتح `/scan.html` على جهاز الاستقبال. العضو يمرّر الكارت، والشاشة تطلع **أخضر** (دخول) أو **أحمر** (ممنوع) مع صوت تنبيه.
5. **التجديد:** من صفحة العضو → "تجديد / اشتراك جديد". لو الاشتراك الحالي لسه ساري، الجديد بيبدأ تلقائيًا بعد نهايته (العضو مابيخسرش أيام). لو منتهي بيبدأ النهارده.

### قواعد الحضور

- الاشتراك المنتهي أو غير الموجود أو العضوية الموقوفة = **رفض** (وبيتسجل في السجل كمحاولة مرفوضة).
- لو نفس العضو اتمسح تاني خلال 5 دقايق، بيتعرض "مكرر" ومابيتسجلش مرتين.
- لو الاشتراك هينتهي خلال 3 أيام، بيظهر تنبيه برتقالي للاستقبال عشان يفكر العضو بالتجديد.

## قراءة الـ QR: ٣ طرق

1. **قارئ باركود/QR USB** (الأفضل للاستقبال): بيتصرف زي الكيبورد. شاشة المسح بتستقبل الكود تلقائيًا من غير ما تضغط حاجة.
2. **كاميرا الجهاز:** بتشتغل على Chrome (أندرويد / ويندوز / ماك). **ما بتشتغلش على Safari في آيفون** لأنه ما بيدعمش الـ API المطلوبة. والكاميرا محتاجة `localhost` أو اتصال **HTTPS**.
3. **كتابة الكود يدويًا** في خانة الإدخال (لو الكارت ضاع أو الكاميرا مش شغالة).

## الاستخدام من أكتر من جهاز

لو الاستقبال هيفتح من موبايل أو جهاز تاني على نفس الشبكة، افتح `http://<عنوان-الجهاز-اللي-شغال-عليه-السيستم>:3000`. الكاميرا في الحالة دي محتاجة HTTPS (مثلًا خلف Nginx أو Caddy أو Cloudflare Tunnel). السيستم بيدعم ده تلقائيًا ويفعّل `Secure` على الكوكي لو وصله `X-Forwarded-Proto: https`.

## الأمان

- كل الـ API محمي بتسجيل دخول (كوكي موقّع وHttpOnly وSameSite=Strict، صلاحيته 12 ساعة).
- حد للمحاولات الغلط في الدخول (5 محاولات / 10 دقايق).
- أكواد الأعضاء عشوائية (40 بت) ومش قابلة للتخمين.
- كل النصوص المعروضة بتتحط كنص عادي (مفيش HTML injection)، وفيه Content-Security-Policy.

## هيكل المشروع

```
server.js      السيرفر والـ API ومنطق الاشتراكات والحضور
db.js          قاعدة البيانات (SQLite المدمجة في Node) والجداول
qr.js          مولّد QR داخلي
public/        الواجهة (لوحة التحكم، شاشة المسح، كارت العضو، الدخول)
test/          اختبارات: فك الـ QR بـ OpenCV، واختبار واجهة بـ Playwright
```

## ملاحظات مهمة

- `node:sqlite` لسه موسومة "تجريبية" في Node، فبيظهر تحذير لو شغلت `node server.js` مباشرة (سكريبت `npm start` بيخفيه). الأداء والاستقرار مناسبين تمامًا لجيم، لكن خد نسخة احتياطية دورية.
- مفيش مدفوعات/فواتير/تجميد اشتراك في النسخة دي (السعر المدفوع بيتسجل مع الاشتراك فقط). ممكن تتضاف لاحقًا.
